Implemented 2026-07-29: a "read-only mode" feature for month-end accounting close. `SystemConfig` is a singleton Prisma model (one row, like a feature flag) cached in memory by `SystemConfigService` (`backend/src/system-config/`), which implements `OnModuleInit` to preload the cached boolean and exposes a `BehaviorSubject`/`Observable` (`statusChanges$`) for live updates.

**Enforcement**: `ReadOnlyModeGuard` (`backend/src/common/guards/read-only-mode.guard.ts`) is registered as a **third** `APP_GUARD` entry in `AppModule` (after `JwtAuthGuard`, `PermissionsGuard` — order matters, added last, existing two untouched). It only blocks `POST/PATCH/PUT/DELETE`; `@Public()` or the new `@BypassReadOnly()` decorator (`backend/src/common/decorators/bypass-read-only.decorator.ts`, same `SetMetadata` pattern as `Public`) exempts a route. The toggle endpoint itself (`POST /system/read-only/toggle`) needs **both** `@Permissions('system.manage')` and `@BypassReadOnly()` — without the bypass, nobody could ever turn the mode back off.

**New permission**: `system.manage` (module `system`), seeded only to `admin` and `accounts_admin` roles (NOT `accounts_assistant`, confirmed by reading current `role-permissions.seed.ts` — the roles are actually named `accounts_admin`/`accounts_assistant` today, not the `accounts_payable_admin`/`accounts_receivable_admin` names in the CLAUDE.md prose, which appears stale/renamed by a concurrent session — [[project_concurrent_claude_sessions]]).

**SSE status endpoint gotcha**: `GET /system/status/stream` (`@Sse('status/stream')` + `@Public()`) manually validates the JWT from `req.query.token` via `JwtService.verify()` (injected by importing `AuthModule`, which re-exports `JwtModule` → `JwtService` — this is the standard way any module gets `JwtService` without redefining `JwtModule.registerAsync`). **Important**: `main.ts`'s global `ResponseFormatInterceptor` (`app.useGlobalInterceptors`, not `APP_INTERCEPTOR`) still runs on SSE routes — confirmed by reading `@nestjs/core`'s `router-execution-context.js`: interceptors wrap the handler's Observable *before* `responseController.sse()` consumes it. Since Nest's SSE writer treats any object emission as-is (only pulling out `.data`/`.id`/`.type`/`.retpry`), the interceptor's `{success, data: originalMessageEvent}` wrapper doesn't break the SSE wire format, but the `success` key is silently dropped by the SSE writer and the client ends up receiving `event.data` = JSON of the *original* `{data: status}` shape (not further nested) — verified by reading `router-response-controller.js`'s `sse()` method. Net effect: the frontend consuming this stream should parse `JSON.parse(event.data).data` as the `SystemStatus` payload, same as any other route in this codebase — no special-casing needed, but worth knowing why it isn't obviously double-wrapped.

Migration for this feature was NOT applied by the agent — schema.prisma was updated and `prisma generate`/`prisma format` were run (codegen/formatting only, no DB writes), per the project's manual-migration Safety Rule. Whoever applies it must still run the CLAUDE.md workaround (`migrate diff` → write SQL → `migrate deploy` → `generate`).
